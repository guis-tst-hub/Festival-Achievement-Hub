# NCPA 校园节日成就平台（本地原型）

这是校园节日扫码成就系统的第一版可运行原型。访客页面采用手机比例；电脑测试时会在右侧显示二维码测试台。管理台先列出活动，进入某个活动后再管理它自己的成就、分类和活动页面。

## 当前功能

- 手机摄像头扫描二维码或访问二维码链接，经过服务器校验后解锁成就
- 手机活动页可直接调用后置摄像头实时扫码；浏览器要求页面使用 HTTPS
- 每个成就可设置总领取上限，同一匿名设备重复扫码不重复占用名额
- 成就进度仅保存在当前浏览器的 `localStorage`
- 服务器只保存活动配置、领取计数和不可逆的匿名设备哈希
- 非当前活动的二维码会提示该活动当前未开放
- 管理台总览只展示活动；成就、分类和活动页面按活动隔离
- 管理员可新建默认未开放的活动，活动编号全局唯一
- 当前活动内可新增、启用或停用成就，设置领取上限、查看计数并清零
- 已有成就和新增成就均可使用 Emoji，或上传 PNG、JPG/JPEG、WebP 自定义图案；本地原型会裁切压缩后随活动配置保存
- 每个活动对应一个活动编号一致的 ZIP 活动包，可下载模板并模拟发布
- 活动开放/关闭状态切换
- 没有任何活动开放时，访客页只显示“活动未开始”，不展示旧活动品牌或内容

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

打开：

- 访客页面：<http://127.0.0.1:3000/>
- 管理台：<http://127.0.0.1:3000/admin>

内置的“展示活动”包含名称为 `1` 到 `6` 的六个测试成就，识别码为 `demo-1` 到 `demo-6`。电脑端可输入识别码测试，手机端只使用实时摄像头扫码。测试进度可在二维码测试台中清空；服务器领取记录需要在管理台中按成就清零。

首次访问接口时，本地开发数据库会自动创建表并写入默认活动。正式部署时应同时应用 `drizzle/` 中的迁移，并持久化数据库目录。

## 活动包格式

活动包必须是 ZIP，根目录至少包含：

```text
manifest.json
index.html
assets/
```

`manifest.json` 示例：

```json
{
  "eventId": "123",
  "name": "展示活动",
  "version": "0.1.0",
  "entry": "index.html"
}
```

进入活动后，可在“活动页面”中下载完整模板。上传包的 `eventId` 必须与当前活动一致。

仓库中的 `examples/showcase-package/` 是编号 `123` 的极简展示活动包源码。当前原型只会检查并模拟发布 ZIP，尚未把上传的 HTML 真正写入服务器；访客页展示的是同一套极简内置页面和在线活动数据。

## 当前边界

这仍是内网测试原型：领取校验数据库已经接入，但管理员登录、真正的活动包发布和 Docker 配置尚未完成。当前管理员写接口没有登录保护，禁止直接暴露到公网。自定义成就图案暂时以压缩数据随活动配置保存，只适合原型；生产版应写入 `/app-data/uploads/` 并只在数据库保存路径。浏览器成就不跨设备同步，清理浏览器数据后会丢失；服务器会保留对应匿名设备的领取记录，重复扫码可恢复本地成就。
